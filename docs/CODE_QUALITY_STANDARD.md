# God View 代码质量评估与质量门禁规范

> 状态：MVP 质量基线
> 关联文档：[技术架构](./TECHNICAL_ARCHITECTURE.md) · [编码规范](./CODING_STANDARDS.md)
> 更新时间：2026-08-07

## 1. 目的

本文将“代码质量好”转换为可检查的标准。质量评估同时关注：

- 功能是否正确；
- Agent 与用户数据是否安全；
- 代码是否容易修改和测试；
- 协议和持久化数据能否兼容演进；
- Extension Host、Webview 和动画是否满足性能预算；
- 错误、取消和恢复路径是否可靠；
- 交互是否可访问。

覆盖率或静态分析分数不能单独代表质量。硬性门禁优先于综合评分。

## 2. 质量治理层级

| 层级            | 运行时机          | 目标                                          |
| --------------- | ----------------- | --------------------------------------------- |
| 本地快速检查    | 提交前            | 在数分钟内发现格式、类型、Lint 和单元测试问题 |
| PR 门禁         | 每个 Pull Request | 阻止正确性、边界、兼容性和安全回退            |
| 主分支/夜间检查 | 合并后定期        | 运行大数据、恢复、性能、Mutation 和跨平台测试 |
| 发布门禁        | 每个版本          | 验证 VSIX、升级、隐私、可访问性和关键用户旅程 |
| 周期性质量评审  | 每月或里程碑结束  | 评估趋势、技术债、缺陷与架构健康度            |

## 3. 不可豁免的硬门禁

以下任一失败时不得合并或发布：

1. TypeScript 类型检查失败；
2. ESLint 或格式检查失败；
3. 单元、契约、集成或相关 E2E 测试失败；
4. 生产构建或 VSIX 打包失败；
5. 协议 Schema 与生成类型/样例不同步；
6. 事件回放不确定，或相同输入产生不同图状态；
7. 存在 package 循环依赖或违反既定依赖方向；
8. 出现未处理的 Critical/High 依赖漏洞且没有获批风险处置；
9. Agent 输入可以绕过 Schema、路径边界、写授权或变化检测；
10. “要求解释”能在批准前修改工作区而未被检测、暂停并标记 `unexpected_write`；
11. 未批准或已过期的修改方案可以创建可写 ChangeSet；
12. 日志、Telemetry 或诊断包泄露 Token、完整源码或用户未授权内容；
13. 数据迁移会丢失无法恢复的事件、标注或快照；
14. 关键视图存在阻止键盘操作的回退，或减少动态效果不可用；
15. 性能关键指标超出已批准预算且没有明确降级或回滚方案；
16. 纳入范围的第一方源文件、项目配置或资源被静默遗漏，或第三方依赖内部文件进入项目图；
17. Codex 或 Claude Code 任一正式 Adapter 未通过公共核心旅程契约测试；
18. 同一工作区可同时存在多个可写 ChangeSet，或分支切换后旧批准仍有效；
19. God View MVP 执行 add、commit、push 或自动回滚用户代码。

紧急安全修复可以缩短非相关测试范围，但不能跳过类型、构建、相关回归测试和安全验证。

## 4. 静态质量标准

### 4.1 编译与 Lint

- 类型错误：0；
- ESLint error：0；
- ESLint warning：0，除非规则明确配置为信息级且有负责人；
- 未使用 export 和依赖：0；
- package 循环依赖：0；
- 非法跨层导入：0；
- 无原因 `eslint-disable`、`@ts-ignore`、`coverage ignore`：0；
- 生产代码 `any`：0；
- 生产代码 `console.*`：0。

### 4.2 复杂度与重复

| 指标             | 目标          | 门禁                   |
| ---------------- | ------------- | ---------------------- |
| 单函数圈复杂度   | ≤ 10          | > 15 阻止合并          |
| 单函数认知复杂度 | ≤ 15          | > 20 阻止合并          |
| 新增代码重复率   | < 3%          | ≥ 5% 阻止合并          |
| 单文件长度       | 建议 ≤ 400 行 | > 600 行需要批准理由   |
| 单函数长度       | 建议 ≤ 60 行  | 超出需评审职责是否混合 |

生成文件、Schema fixture 和有明确原因的数据表可排除长度/重复指标，但必须在工具配置中显式列出。

### 4.3 依赖健康

- 新生产依赖完成许可证、维护状态、bundle 体积和安全评估；
- 同类能力不得重复引入多个库；
- 未使用依赖为 0；
- 原生依赖必须有 ADR 和三平台打包证明；
- Critical/High 漏洞为 0；Medium 漏洞必须有风险记录和处理日期；
- 锁文件变化必须能由 manifest 变化解释。

## 5. 测试覆盖标准

### 5.1 覆盖率阈值

覆盖率以 changed-lines 和 package 两个维度检查。新代码不能依赖历史低覆盖率掩盖。

| 包/区域                    | Lines | Branches | Functions |
| -------------------------- | ----: | -------: | --------: |
| `protocol`                 |   95% |      90% |       95% |
| `graph-core`               |   95% |      90% |       95% |
| `annotation-core`          |   90% |      85% |       90% |
| `storage`                  |   90% |      85% |       90% |
| `validation-core`          |   90% |      85% |       90% |
| 语言 Validator             |   85% |      80% |       85% |
| VS Code Extension adapters |   80% |      75% |       80% |
| Webview 非视觉逻辑         |   85% |      80% |       85% |
| Webview 组件整体           |   75% |      70% |       75% |
| 全仓 changed-lines         |   90% |      85% |       90% |

以下代码不能仅靠覆盖率判断：

- 图渲染样式和动画视觉效果；
- VS Code 平台集成；
- 并发、恢复、文件损坏；
- 可访问性；
- Agent 跨进程交互。

它们需要专项集成、E2E、故障注入或人工验证。

### 5.2 必测路径

#### Protocol

- 每个 Schema 的合法、边界和非法样例；
- 未知字段与 minor 兼容；
- major 不兼容拒绝；
- 稳定错误码；
- 生成物与真源一致。

#### Graph State

- 所有事件 reducer；
- 重复、乱序、缺失前置事件；
- 所有合法和非法状态转换；
- 相同事件序列确定性回放；
- Snapshot + 尾部事件与全量回放一致；
- 实体删除、移动和标注重连；
- 稳定模块 ID 在改名、Agent 切换和分支派生后保持一致；
- 第一方文件全部归类或进入“未分类”，排除原因可重现；
- Agent 伪造 `CoverageReport/codeValidation/userConfirmation` 字段时被 Schema 或命令处理层拒绝；

#### Annotation & Agent Task

- 解释任务启动时没有 God View 写入授权，且不持有写租约；
- `request_write_access` 只产生升级请求，不授予权限；用户批准方案后才可创建可写 ChangeSet；
- WriteAccessRequest、ChangeProposal、批准记录和 ChangeSet 使用独立 ID 并可端到端追溯；
- 上下文最小化和用户删减；
- 方案批准、拒绝、取消和澄清；
- 旧 map/Git revision 使批准失效；
- Annotation → Proposal → ChangeSet → Diff 可追溯；
- Agent 回答证据引用不存在时降级处理；
- Adapter 准确声明 `enforced` 或 `monitored` 权限模式；支持时强制批准路径作用域，不支持时明确警示并监控文件/Git 变化；
- 批准前写入产生 `unexpected_write`、暂停任务并保留可见 Diff，且不能事后伪造批准；
- `unexpected_write` 属于尚未获授权的托管 Agent 任务，不得创建或伪造一个已批准 ChangeSet 来承载该异常；
- 无可靠任务关联证据时，意外变化必须标为未知/外部来源，不得错误归因给 Codex 或 Claude Code；
- 越界写入产生 `scope_violation`、暂停任务并保留可见 Diff；
- 当前工作区已有 Diff 与 Agent 新 Diff 分离；
- 单写租约、分支切换、重叠外部写入和中断状态；
- 无 Git 工作区拒绝可写 ChangeSet；
- 接受结果不改变 Git index 或提交历史。
- 外部 Agent/未知进程写入与 God View managed task 明确区分，不产生伪造批准记录。

#### Storage

- 半写、损坏、重复和超大事件；
- 快照原子替换；
- 迁移成功、失败回滚和中断恢复；
- 工作区移动或身份变化；
- 分支状态和用户布局隔离；
- 30 天清理后可从压缩快照恢复当前地图；
- 未解决/固定标注不会被误删，解决标注正文按策略到期；
- Diff 元数据不包含完整源码内容；
- 清除数据的精确范围。

#### Security

- `../`、绝对路径、编码路径和符号链接逃逸；
- 恶意 Markdown、HTML、SVG 和脚本 payload；
- Token、环境变量和源码日志脱敏；
- 未批准写入、过期批准和跨 workspace session；
- 不受信任工作区的功能降级。

## 6. 测试层次

| 测试类型         | 主要对象                         | 频率                     |
| ---------------- | -------------------------------- | ------------------------ |
| 单元测试         | reducer、状态机、过滤、校验规则  | 每次 PR                  |
| 属性测试         | 幂等、回放、序列化、随机事件序列 | 每次 PR 的短集；夜间长集 |
| Schema 契约测试  | Agent、Webview、存储消息         | 每次 PR                  |
| Adapter 契约测试 | Codex/Claude/MCP 能力转换        | 每次相关 PR              |
| 组件测试         | 详情、标注、播放控制             | 每次 PR                  |
| VS Code 集成测试 | 激活、命令、文件、Git、生命周期  | 每次 PR 或主分支         |
| Webview E2E      | 搜索、聚焦、讲解、标注、审批     | 每次 PR 的关键集         |
| 故障注入         | 崩溃、损坏、迟到事件、进程中断   | 夜间/发布                |
| 性能基准         | 大图、回放、校验、动画           | 主分支趋势/发布          |
| 人工探索         | 可理解性、动画节奏、平台差异     | 发布候选                 |

### 6.1 测试可靠性要求

- flaky test 不允许简单重试后长期忽略；首次发现即记录并指定负责人；
- 7 天内同一测试出现 2 次非产品原因失败，必须隔离并修复；
- 被隔离测试不得覆盖发布关键路径，且有最晚修复日期；
- 测试不访问真实网络、用户 Agent 账号或个人文件；
- 固定等待超过 100 ms 需要说明，优先等待状态或使用虚拟时间；
- 跨平台路径测试至少覆盖 POSIX 与 Windows 语义。

## 7. 性能质量标准

下列产品预算来自 PRD。Stage 0 原型需要在固定机器和数据集上验证并固化测量方法；验证前可调整目标，但一旦形成基线，任何调整都必须附数据、原因和 ADR/评审记录，不能为了让单个 PR 通过而降低门槛。

### 7.1 产品预算

| 指标                              |                 MVP 门槛 |
| --------------------------------- | -----------------------: |
| Agent 事件接收到地图可见 P95      |                 ≤ 300 ms |
| 5,000 节点快照首次可交互 P95      |                    ≤ 3 s |
| 10,000 语义实体全图概览可交互 P95 |                    ≤ 5 s |
| 单文件保存后增量校验 P95          |                    ≤ 1 s |
| 点击、暂停、切换讲解步骤反馈 P95  |                 ≤ 100 ms |
| 常规项目动画                      | 目标 60 FPS，最低 30 FPS |
| Extension Host 单次同步阻塞       |                 ≤ 100 ms |
| 纳入第一方文件地图归属            |       100%，允许“未分类” |
| 第三方依赖内部文件节点            |                        0 |

### 7.2 工程预算

- 未打开 God View 时，扩展不得进行持续高 CPU 图计算；
- 5,000 节点交互基准中不得因 hover 或单节点选择触发全图布局；
- 100K 事件回放和快照性能在 Stage 0 固化绝对预算；
- 主分支性能相对最近稳定基线退化超过 10% 时告警，超过 20% 时阻止发布；
- Webview 初始 JS gzip 体积和 VSIX 体积在 Stage 0 建立预算，之后增长超过 10% 需要说明；
- 性能报告记录机器、数据集、版本、重复次数和 P50/P95，不比较单次偶然结果。

### 7.3 降级验证

必须验证：

- 关闭粒子动画后讲解仍能理解；
- 超大图在同一画布自动进行 LOD、关系聚合和视口裁剪，不丢失覆盖率、搜索或实体寻址；
- Validator 超时不阻塞地图浏览；
- Agent 离线时本地地图、标注和历史可用；
- Worker 崩溃后可重启且 Extension Host 不崩溃；
- 内存压力下可以暂停后台校验和释放不可见图数据。

## 8. 安全与隐私质量标准

### 8.1 每个相关 PR 的检查

- 输入来源和信任级别是否明确；
- 是否使用运行时 Schema 验证；
- 路径是否限制在授权 workspace；
- 是否新增代码、标注、命令或身份信息的存储/传输；
- 日志和错误是否可能泄露 payload；
- 解释与修改权限是否严格分离；
- 是否需要更新威胁模型和隐私说明。

### 8.2 发布检查

- 对 Agent Gateway、Webview bridge、Markdown 渲染和路径解析进行专项安全测试；
- 依赖漏洞与许可证扫描通过；
- CSP 无非预期放宽；
- 诊断包人工检查不包含密钥和完整源码；
- 清除本地数据后不存在未说明副本；
- 云端 Agent 的数据边界在 UI 可见；
- 不受信任工作区默认禁止写入和外部命令。

发现可利用的跨 workspace 读写、未授权 Agent 写入、Token 泄露或任意脚本执行，均按最高严重级别处理。

## 9. 协议与数据兼容质量

- 新版本必须读取上一稳定版本的快照和事件；
- minor 版本消费者忽略未知可选字段；
- 迁移运行两次结果相同；
- 迁移失败不修改原始数据；
- 迁移后的图在语义上与迁移前一致；
- 事件 replay hash 在受支持平台一致；
- 至少保留一个上一版本 fixture 进入永久回归集；
- 删除兼容代码前必须先移除支持承诺并提供用户迁移路径。

## 10. UX 与可访问性质量

### 10.1 自动检查

- 关键 Webview 页面 axe Critical/Serious 问题为 0；
- 控件存在可访问名称；
- 键盘焦点可见且顺序合理；
- 状态不只依赖颜色；
- 文本和图标对比度满足适用 WCAG 2.2 AA；
- reduced motion 测试覆盖讲解、布局、节点状态和变更回放。

### 10.2 人工任务检查

发布候选必须能仅用键盘完成：

1. 打开概览；
2. 搜索并聚焦节点；
3. 播放、暂停和切换讲解步骤；
4. 创建“要求解释”标注；
5. 展开 Agent 证据；
6. 查看并拒绝修改方案；
7. 返回概览。

同时验证屏幕阅读器的步骤播报，以及高对比度主题下节点、关系和标注状态。

## 11. 综合质量评分

综合评分用于发布评审和趋势分析，不能覆盖硬门禁。

| 维度             | 权重 | 满分条件摘要                                    |
| ---------------- | ---: | ----------------------------------------------- |
| 正确性与测试     |   25 | 覆盖率达标，关键状态/恢复路径完整，无已知 P0/P1 |
| 可维护性         |   20 | 边界清晰、复杂度/重复达标、无循环依赖、文档同步 |
| 协议与数据可靠性 |   15 | 契约兼容、确定性回放、迁移与恢复全部通过        |
| 性能与稳定性     |   15 | 所有预算通过，无显著回退，降级路径有效          |
| 安全与隐私       |   15 | 威胁检查、权限、路径、脱敏和依赖扫描通过        |
| UX 与可访问性    |   10 | 核心任务、键盘、对比度和 reduced motion 通过    |

评分等级：

- A：90–100，可发布；
- B：80–89，可合并；发布需要 ≥ 85 且无关键维度低于 70%；
- C：70–79，只允许进入实验分支或带修复计划的内部版本；
- D：< 70，不可发布。

评分证据必须链接到 CI、基准测试、缺陷、审查或人工验证记录，禁止凭主观印象打分。

## 12. Pull Request 质量门禁

### 12.1 所有 PR

- format、lint、typecheck；
- changed-lines 覆盖率；
- 相关 unit/contract tests；
- package 边界与循环依赖；
- 构建；
- 依赖与 secret scan；
- PR 模板完整；
- 文档与生成文件一致。

### 12.2 条件门禁

| 变更类型                    | 额外要求                                                                                   |
| --------------------------- | ------------------------------------------------------------------------------------------ |
| Protocol/Schema             | 兼容测试、样例、迁移说明、Adapter contract test                                            |
| Graph reducer/state machine | 属性测试、回放确定性、非法转换测试                                                         |
| Storage/migration           | 故障注入、备份恢复、上一版本 fixture                                                       |
| Agent 写权限                | 安全评审、写入申请、意外写入、过期批准和跨 workspace 测试                                  |
| Agent Adapter               | Codex/Claude 公共 contract suite、能力矩阵、`enforced/monitored`、权限升级、取消和错误映射 |
| Git/分支状态                | 脏工作区、单写租约、切分支、冲突、中断、无 Git 降级                                        |
| Webview 交互                | Playwright、键盘、axe、截图/录屏                                                           |
| 动画/布局                   | 帧率、reduced motion、视觉回归                                                             |
| Validator                   | 正确/错误/不支持样例、取消和超时                                                           |
| 性能关键路径                | 基准数据和前后对比                                                                         |
| 新生产依赖                  | 依赖评估和 bundle 体积变化                                                                 |

## 13. 发布质量门禁

发布候选必须满足：

1. 所有硬门禁通过；
2. 综合评分 ≥ 85；
3. P0/P1 未解决缺陷为 0；
4. P2 缺陷有用户影响说明和后续计划；
5. Windows、macOS、Linux 本地 Git 工作区的最低支持组合通过 smoke test；
6. Remote/SSH、WSL、Dev Container 记录 Beta 兼容性结果，不作为首个 MVP 阻断项；
7. 上一稳定版本升级和数据迁移通过；
8. 新安装、无 Agent、Agent 离线、无 Git 和不受信任工作区降级正常；
9. VSIX 安装、激活、卸载和数据清理行为符合说明；
10. 更新 CHANGELOG、隐私说明、已知限制和回滚方案。

## 14. 缺陷分级

| 等级 | 定义示例                                            | 处理原则                     |
| ---- | --------------------------------------------------- | ---------------------------- |
| P0   | 数据丢失、跨 workspace 写入、密钥泄露、任意代码执行 | 立即停止发布，优先修复和通知 |
| P1   | 未批准修改、地图严重错误且标为已验证、扩展频繁崩溃  | 阻止发布，当前里程碑修复     |
| P2   | 主要功能受损但有绕行、明显性能或可访问性问题        | 排入最近版本并跟踪           |
| P3   | 轻微视觉、文案或边缘体验问题                        | 正常优先级管理               |

缺陷修复必须增加回归测试。无法自动化时记录稳定的人工复现和验证步骤。

## 15. 技术债与质量趋势

每个技术债条目必须包含：

- 影响的用户或工程行为；
- 产生原因；
- 当前风险；
- 建议方案；
- 负责人和目标里程碑；
- 可验证的完成条件。

每月关注以下趋势，而非单次数字：

- escaped defects 和回归缺陷；
- flaky tests 数量与平均修复时间；
- 复杂度、重复和依赖环；
- 性能 P50/P95 与内存；
- Schema/迁移失败；
- Agent 事件拒绝、漂移和过期方案；
- 安全漏洞年龄；
- 标注解释的证据完整率；
- 用户完成关键任务的时间。

连续两个周期恶化的指标必须产生明确改进任务。

## 16. 质量豁免

除“不可豁免硬门禁”外，临时豁免必须记录：

1. 未达标指标和当前数值；
2. 用户/系统风险；
3. 缓解措施；
4. 负责人；
5. 到期日期；
6. 对应修复事项。

豁免最长一个发布周期，到期自动失效。不得连续以同一理由延期。
